# 1.3 데이터 저장 구조 및 I/O 메커니즘
`I/O 튜닝이 곧 SQL 튜닝이다.`
## 1.3.1 SQL이 느린 이유
- SQL이 느린 이유는 디스크 I/O 때문이다.
    - I/O = 잠(SLEEP)
        - OS 또는 I/O 서브시스템이 I/O를 처리하는 동안 프로세스는 잠을 잔다.
    - 프로세스 = 실행 중인 프로그램
        - 생성 이후 종료 전까지 준비, 실행, 대기 상태를 반복
        - 디스크에서 데이터를 읽어야 할 땐 CPU를 OS에 반환하고 잠시 수면(waiting) 상태에서 I/O가 완료되기를 기다린다.
- I/O Call 속도는 Single Block I/O 기준 평균 10ms
    - 초당 100 블록을 읽는다.
    - 큰 캐시를 가진 SAN 스토리지는 4~8ms쯤 되어 초당 125~250 블록을 읽는다.
    - SSD까지 활용하는 스토리지는 1~2ms, 초당 500~1,000 블록을 읽는다.
    - SQL이 Singlo Block I/O 방식으로 10,000 블록을 읽으면 10초 이상 기다려야 한다.
        - I/O 튜닝이 안되어 있는 시스템이면 디스크 경합이 심해지는 만큼 대기 시간도 늘어난다.
