# 4.2 소트 머지 조인
- 옵티마이저가 NL 조인 대신 소트 머지 조인이나 해시 조인을 선택하는 경우
    - 조인 컬럼에 인덱스가 없을 때
    - 대량 데이터 조인이어서 인덱스가 효과적이지 않을 때
- 해시 조인이 등장해서 소트 머지 조인을 많이 쓰진 않지만 해시 조인을 사용할 수 없는 상황에서 대량 데이터를 조인할 때 유용
## 4.2.1 SGA vs. PGA
- SGA(System Global Area / Shared Global Area)
    - 공유 메모리 영역
        - 여러 프로세스가 공유할 수 있음
        - 래치(Latch)가 존재하여 동시에 액세스는 불가
            - 프로세스 간 액세스 직렬화를 위한 Lock 메커니즘
    - DB 버퍼캐시에서 블록을 읽으려면 버퍼 lock을 얻어야 한다.
- PGA(Private Global Area)
    - 각 오라클 서버 프로세스에 할당된 메모리 영역
        - 다른 프로세스와 공유하지 않는 독립적인 메모리 공간
        - 래치 메커니즘이 불필요해서 같은 양의 데이터를 읽더라도 SGA 버퍼캐시보다 훨씬 빠름
    - 프로세스에 종속적인 고유 데이터를 저장하는 용도로 사용
    - 할당받은 PGA 공간이 작아 데이터를 모두 저장할 수 없으면 Temp 테이블스페이스를 이용
## 4.2.2 기본 메커니즘
- 소트 단계
    - 양쪽 집합을 조인 컬럼 기준으로 정렬
- 머지 단계
    - 정렬한 양쪽 집합을 서로 머지(Merge)
- use_merge 힌트로 유도
    - 사원 테이블 기준으로(ordered) 고객 테이블과 조인할 때 소트 머지 조인 방식을 사용(use_merge)
    ```sql
    select /*+ ordered use_merge(c) */
            e.사원번호, e.사원명, e.입사일자,
            c.고객번호, c.고객명, c.전화번호, c.최종주문금액
    from    사원 e, 고객 c
    where   c.관리사원번호 = e.사원번호
    and     e.입사일자 >= '19960101'
    and     e.부서코드 = 'Z123'
    and     c.최종주문금액 >= 20000
    ```
    - ordered
        - FROM 절에 기술한 순서대로 조인하라고 옵티마이저에 지시하는 힌트    
        - ordered 대신 leading(e) 힌트 사용 가능        
    - 소트 단계
        ```sql
        select   사원번호, 사원명, 입사일자
        from     사원
        where    입사일자 >= '19960101'
        and      부서코드 = 'Z123'
        order by 사원번호
        ```
        - 조건에 해당하는 사원 데이터를 읽어 조인 컬럼인 사원번호 순으로 정렬
        - 정렬한 결과집합은 PGA 영역에 할당된 Sort Area에 저장
        - 정렬한 결과집합이 PGA에 담을 수 없을 정도로 크면, Temp 테이블스페이스에 저장
        ```sql
        select   고객번호, 고객명, 전화번호, 최종주문금액, 관리사원번호
        from     고객
        where    최종주문금액 >= 20000
        order by 관리사원번호
        ```
        - 조건에 해당하는 고객 데이터를 읽어 조인 컬럼인 관리사원번호 순으로 정렬
        - 정렬한 결과집합은 PGA 영역에 할당된 Sort Area에 저장
        - 정렬한 결과집합이 PGA에 담을 수 없을 정도로 크면, Temp 테이블스페이스에 저장
    - 머지 단계
        ```sql
        begin
            for outer in (select * from PGA에_정렬된_사원)
            loop    --outer 루프
                for inner in (select * from PGA에_정렬된_고객
                              where 관리사원번호 = outer.사원번호)
                loop    --inner 루프
                    dbms_output.put_line ( ··· );
                end loop;
            end loop;
        end;
        ```
        - PGA(또는 Temp 테이블스페이스)에 저장한 사원 데이터를 스캔하면서 
        - PGA(또는 Temp 테이블스페이스)에 저장한 고객 데이터와 조인
        - NL 조인과 다르지 않음
        - 사원 데이터 기준으로 고객 데이터를 매번 Full Scan하지 않음
            - 고객 데이터가 정렬돼 있어서 조인 대상 레코드가 시작되는 지점을 쉽게 찾고
            - 조인에 실패하는 레코드를 만나면 바로 멈출 수 있음
        - Sort Area에 저장한 데이터 자체가 인덱스 역할을 함
            - 소트 머지 조인은 조인 컬럼에 인덱스가 없어도 사용 가능
            - 조인 컬럼에 인덱스가 있어도 NL 조인은 대량 데이터 조인 시 불리해서 소트 머지 조인 사용 가능
## 4.2.3 소트 머지 조인이 빠른 이유
- NL 조인은 모든 DBMS가 공통으로 제공하는 전통적인 조인 방식
    - 대량 데이터 조인 시 성능이 매우 느림
    - 소트 머지 조인과 해시 조인이 개발된 이유
    - 인덱스를 이용한 조인 방식
        - 조인 과정에서 액세스하는 모든 블록을 랜덤 액세스 방식으로 `건건이` DB 버퍼캐시를 경유해서 읽음
        - 인덱스든 테이블이든, 읽는 모든 블록에 래치 획득 및 캐시버퍼 체인 스캔 과정을 거침
        - 버퍼캐시에서 찾지 못한 블록은 `건건이` 디스크에서 읽어 들임
- 소트 머지 조인은 양쪽 테이블로부터 조인 대상 집합(조인 조건 이외 필터 조건을 만족하는 집합)을 `일괄적으로` 읽어 PGA(또는 Temp 테이블스페이스)에 저장 후 조인
    - PGA는 프로세스만을 위한 독립적인 메모리 공간이고 데이터를 읽을 때 래치 획득 과정이 없어 대량 데이터 조인에 유리
## 4.2.4 소트 머지 조인의 주요 용도
- 대부분 해시 조인이 더 빠름
    - 해시 조인은 조인 조건식이 등치(=) 조건이 아니면 사용 불가
- 조인 조건식이 등치(=) 조건이 아닌 대량 데이터 조인
- 조인 조건식이 아예 없는 조인(Cross Join, 카테시안 곱)
## 4.2.5 소트 머지 조인 제어하기
- 소트 머지 조인 실행계획
    ```
    Execution Plan
    ---------------------------------------------------------------------------
    0     SELECT STATEMENT Optimizer=ALL_ROWS
    1   0   MERGE JOIN
    2   1     SORT (JOIN)
    3   2       TABLE ACCESS (BY INDEX ROWID) OF '사원' (TABLE)
    4   3         INDEX (RANGE SCAN) OF '사원_X1' (INDEX)
    5   4     SORT (JOIN)
    6   5       TABLE ACCESS (BY INDEX ROWID) OF '고객' (TABLE)
    7   6         INDEX (RANGE SCAN) OF '고객_X1' (INDEX)
    ```
    - 양쪽 테이블에 각각 소트한 후, 위쪽 사원 테이블 기준으로 아래쪽 고객 테이블과 머지 조인한다.
    - 소트할 대상을 찾기 위해 각 테이블을 액세스할 때 인덱스를 이용
    - 인덱스를 이용하지 않고 Table Full Scan으로 처리도 가능
## 4.2.6 소트 머지 조인 특징 요약
- 조인을 위해 실시간으로 인덱스를 생성하는 것과 같음
- 양쪽 집합을 정렬한 후 NL 조인과 같은 방식으로 진행하지만, PGA 영역에 저장한 데이터를 이용해 더 빠름
    - 소트 부하만 감수하면, `건건이` 버퍼캐시를 경유하는 NL 조인보다 빠름
- NL 조인은 조인 컬럼에 대한 인덱스 유무에 크게 영향을 받지만, 소트 머지 조인은 영향을 받지 않음
    - 양쪽 집합을 개별적으로 읽고 나서 조인을 시작하여 조인 컬럼에 인덱스가 없는 상황에서 유리
- 스캔 위주의 액세스 방식을 사용
    - 모든 처리가 스캔 방식으로 이루어지진 않음
